# task-creator

Превращает сырую идею или устное описание в полное ТЗ, по которому задачу можно реализовать без дополнительных вопросов — самим агентом или человеком.

## Когда использовать

- Пользователь просит: «составь задачу», «оформи как задачу», «подготовь ТЗ», «напиши спеку»
- Фича сформулирована одной фразой, и её нужно развернуть до реализуемого описания
- Готовится задача для issue tracker, коммита или будущей сессии агента

## Процесс

### 1. Собери контекст

- Перечитай описание задачи от пользователя, задай уточняющие вопросы, если что-то критично неоднозначно (не более 3–5 вопросов).
- Изучи кодовую базу: какие файлы затронет фича, как устроены смежные части, есть ли похожий код, который можно переиспользовать.
- Для этого проекта (vcode): архитектура и API описаны в корневом `AGENTS.md`. Весь UI — один файл `apps/frontend/index.html`; backend — `apps/backend/server.js` (SQLite через `node:sqlite`, без npm-зависимостей). Изменения API/БД требуют правки и Dockerfile/docker-compose.yml при необходимости.

### 2. Заполни шаблон

Возьми шаблон из [references/task-template.md](references/task-template.md) и заполни все секции. Правила:

- **Не оставляй пустых секций** — если секция неприменима, напиши «Не требуется» и почему.
- Требования формулируй как проверяемые утверждения («при клике X происходит Y»), а не как пожелания.
- Критерии приёмки — конкретные и воспроизводимые: их можно прогнать вручную в браузере или curl'ом по API.
- Указывай точные пути файлов и точные имена эндпоинтов/полей БД.
- Отмечай edge cases явно: пустые значения, граничные длины, одновременные правки, отсутствие данных.

### 3. Проверь задачу перед выдачей

Чек-лист готовности:

- [ ] По описанию можно начать реализацию без дополнительных вопросов
- [ ] Все затронутые файлы перечислены и существуют (или явно помечены «создать»)
- [ ] Критерии приёмки проверяемы
- [ ] Для vcode: если меняется API или схема БД — упомянуты миграция/совместимость и необходимость `./deploy.sh`
- [ ] Нет противоречий между секциями

### 4. Выдай результат

- Выдай готовое ТЗ одним блоком Markdown (можно сразу сохранить в файл по указанию пользователя, например `tasks/<name>.md`).
- Если пользователь хочет, предложи сразу реализовать задачу.
