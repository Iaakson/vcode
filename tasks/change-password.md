# Личный кабинет и смена пароля

## Простыми словами
Вверху главной страницы появится ссылка «Личный кабинет». В нём видно ваше имя и сколько у вас задач. Там же есть кнопка «Сменить пароль»: открывается отдельная страница, где нужно ввести старый пароль и дважды новый. Если старый пароль верный и оба новых совпадают — пароль меняется, и дальше вы входите уже с новым паролем.

## Контекст
Сейчас пользователь не может изменить свой пароль: пароль задаётся только при регистрации (а администратором — через админ-панель, задача `tasks/admin-panel.md`). Задача добавляет страницу личного кабинета со сменой собственного пароля.

## Цель
Пользователь видит в личном кабинете свои имя и число задач и может сам сменить свой пароль, подтвердив старый.

## Требования
1. В шапке главного экрана появляется ссылка «Личный кабинет» (в стиле приложения, рядом с существующими элементами шапки; у неавторизованного пользователя её нет — шапка показывается только после входа).
2. Страница личного кабинета (`/profile`) открывается по адресу `/profile` (fallback на `index.html` для неизвестных путей — по образцу задачи `admin-panel.md`).
3. На странице личного кабинета: текущий `username` и число задач пользователя. Число задач берётся из уже загруженного `GET /api/todos` (длина списка) — отдельный эндпоинт не нужен.
4. Кнопка «Сменить пароль» ведёт на страницу смены пароля (`/profile/password`): поля «Старый пароль», «Новый пароль», «Повторите новый пароль», кнопка «Сохранить».
5. `POST /api/change-password {oldPassword, newPassword}` (только авторизованный):
   - `oldPassword` неверный → 400, пароль не меняется;
   - `newPassword` короче 4 символов → 400;
   - новый пароль не совпадает с повтором — проверка только на клиенте (сервер сравнивает только `oldPassword`);
   - при успехе: новый `salt`, scrypt-хэш (как при регистрации), сессия остаётся активной, ответ 200.
6. После успешной смены показывается подтверждение и происходит возврат в личный кабинет (или на главную).
7. Неавторизованный доступ: `POST /api/change-password` → 401; страницы `/profile` → редирект на главную.
8. Тёмная тема работает на новых страницах (общий стиль приложения).

## API / БД
```
POST /api/change-password — {oldPassword, newPassword} → 200 | 400 | 401
```

Схема БД: Не требуется — обновляются существующие поля `password_hash`/`salt` таблицы `users`.

## Edge cases
- Неверный старый пароль → 400, пароль не меняется.
- Новый пароль короче 4 символов → 400 (и клиентская валидация с понятным сообщением).
- Поля «Новый пароль» и «Повтор» не совпадают → клиент не отправляет запрос, показывает сообщение.
- Новый пароль совпадает со старым → разрешено (200), бессмысленно, но не ошибка.
- Неавторизованный → 401 (API) / редирект (UI).
- После смены пароля текущая сессия жива; старые сессии на других устройствах тоже остаются активными (не выкидываем — отмечено явно, как в `admin-panel.md`).
- Новый пароль не совпадает с подтверждением — проверка только на клиенте (сервер сравнивает только `oldPassword`).

## Критерии приёмки
- [ ] `curl -c c1 -X POST localhost:3001/api/register -d '{"username":"u1","password":"pass1"}'` → 201; `GET /api/todos` с c1 → 200 (список, длина = число задач)
- [ ] `POST /api/change-password` с c1 `{oldPassword:"wrong", newPassword:"newpass1"}` → 400; логин `u1/pass1` всё ещё работает
- [ ] `POST /api/change-password` с c1 `{oldPassword:"pass1", newPassword:"123"}` → 400 (короткий)
- [ ] `POST /api/change-password` с c1 `{oldPassword:"pass1", newPassword:"newpass1"}` → 200; логин `u1/newpass1` → 200; логин `u1/pass1` → 401
- [ ] Сессия c1 после смены остаётся действительной: `GET /api/me` → 200
- [ ] `POST /api/change-password` без сессии → 401
- [ ] В UI: ссылка «Личный кабинет» в шапке, страница показывает имя и число задач; смена пароля через форму работает, при несовпадении новых паролей — сообщение без запроса к серверу

## Сценарии для тестирования
(e2e — `tests/e2e`, принципы — `docs/testing.md`)
- позитив: register → login → `POST /api/change-password {oldPassword, newPassword}` → 200; повторный логин с новым паролем → 200; со старым → 401
- сессия жива после смены: `GET /api/me` с той же cookie → 200
- негатив: неверный старый пароль → 400
- негатив: новый пароль короче 4 символов → 400
- негатив: `POST /api/change-password` без сессии → 401

## План реализации
1. Backend: `POST /api/change-password` — проверка `oldPassword` через существующий `hashPassword`, генерация нового `salt`, обновление `users`.
2. Frontend: ссылка «Личный кабинет» в шапке, роутинг `/profile` и `/profile/password`, страницы и формы, стили (тёмная тема).
3. Прогнать тесты: `npm test` (unit + e2e), добавить e2e-сценарии из секции выше.
